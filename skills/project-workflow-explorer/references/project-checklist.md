# 项目检查表

当需要生成 CSV 检查表或校验最终报告时读取本文件。

| 类别 | 必查项 | 关键字段 | 主源 | 佐证源 | 通过标准 |
| --- | --- | --- | --- | --- | --- |
| 范围 | 项目入口 | 页面 ID、空间、标题、子页面、最后修改时间 | Confluence 目录图谱 | 页面索引 | 主线和排除项清楚 |
| 范围 | 主线边界 | 产品线、芯片、机型、系列、排除方向 | 项目页面 | 用户背景 | 相邻项目没有混入 |
| 基础 | 实体卡片 | 机型、平台、Jira、SVN、repo、manifest、主干分支 | 项目机型页 | 分支页 | 最小项目实体存在 |
| 基础 | 开发准备 | 规格、方案、调试、烧录、认证、原型机 | 方案页面 | 附件和链接 | 开发入口清楚 |
| 需求 | 需求池 | 需求、PRD、评估、工作量、负责人、输入时间 | 需求页面 | PRD 或评估文档 | 至少有样例可追踪 |
| 需求 | 需求闭环 | PRD 正文、SRS、任务、版本计划、测试用例 | Confluence 和 SVN | Jira 和 PLM | 需求不只停留在标题 |
| 变更 | 变更影响 | 来源、CR、机型、软件影响、资料、Jira Key | 变更表 | Jira Change 和 PLM | 原因和影响可解释 |
| 变更 | 审批实施 | 评估、审批、实施、确认、关闭状态 | Jira Change 或 PLM | Confluence | 状态和业务内容一致 |
| 设计 | 设计产物 | SDS、系统设计、模块设计、评审记录、映射关系 | SVN | Jira Review 和 KOA | 路径或 Review Key 可追溯 |
| 代码 | 开发证据 | commit、patch、自测、Review、静态检查、安全检查 | repo 和 SVN | Jira Review | 实现能映射需求或变更 |
| 分支 | 分支图谱 | 主干、IR、OTA、发布、tag、状态、拉出时间 | 分支表 | repo 和 MTK tag | 用途和状态清楚 |
| 分支 | 基线对齐 | version 文件、SW Version、MTK tag、确认邮件 | 分支表和 repo | 邮件和配置管理 | 不能只看分支名 |
| 构建 | 版本包 | 任务、分支、版本、路径、机型、生成时间 | Jenkins 或版本路径 | Confluence 和 TV-SLM | 有版本包证据或缺口明确 |
| 测试 | LIT 和 SIT | 计划、用例、报告、问题列表、回归结论 | SVN 和 Confluence | Jira 和 TV-SLM | 测试输出物已归档 |
| 测试 | 问题质量 | 前置条件、步骤、log、概率、图片、设备、等级 | Jira 和测试规范 | Confluence | 问题可复现可回归 |
| 质量 | 市场问题 | 现象、机型、模块、类型、负责人、原因、解决、预防 | 质量页面 | Jira 和 OTA 数据 | 复盘字段完整 |
| 质量 | 技术专题 | 问题类型、根因、措施、验证方法、负责人 | 专题页面 | 测试报告 | 技术措施可复用 |
| 发布 | 发布前门禁 | 测试结论、目标分支、version 文件、版本包、范围 | 分支和版本页面 | TV-SLM 和邮件 | 发布证据存在或缺口明确 |
| 发布 | OTA 台账 | OTA 名称、PLM 任务、平台、机型、原因、主设计 | OTA 页面 | PLM | 只证明进入发布记录 |
| 发布 | 灰度结果 | 批次、比例、成功率、失败率、投诉、暂停、全量时间 | OTA 平台或 PLM | Confluence | 发布效果可评估 |
| 复盘 | 闭环沉淀 | 根因、修复、预防、效果数据、回灌结论 | 质量页面 | Jira 和 PLM | 经验已写回知识库 |

| 治理 | 未闭合问题 | 缺口、影响、优先级、验证动作、停止条件 | 汇总报告 | 用户确认 | 后续动作可执行 |

## 资料源规则

- Confluence 用于项目事实和流程解释。
- Jira 用于状态和执行跟踪。
- SVN 用于设计、代码 Review、LIT、SIT 归档。
- PLM 用于项目或变更基线证据。
- TV-SLM 或 SLM 用于转测和版本质量状态。
- KOA 只用于流程和模板规则。
- repo、MTK tag 和 version 文件用于代码基线证据。
- Jenkins 或版本路径用于构建产物。
- 邮件作为确认证据时，必须记录主题、时间、分支、问题、确认人、结论和归档位置。

## 冲突处理规则

- Confluence 业务事实和 Jira 状态不一致时，标记为状态冲突。
- Confluence 记录变更存在但 PLM 未更新时，标记为基线缺口。
- Jira 已关闭但没有测试报告或版本计划时，只能写执行状态关闭，不能写交付闭环。
- OTA 数据有 MT9655 但没有分支名时，不能推断具体 OTA 分支。
- 分支表要求同步 version 文件但没有 export 值或 commit 时，只能写必查点。
