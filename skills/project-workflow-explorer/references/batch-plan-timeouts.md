# 分批规划和超时策略

当需要规划长期项目探索或拆分多 agent 工作时读取本文件。

## 默认批次

| 批次 | 主题 | 目标 |
| --- | --- | --- |
| batch0 | 范围 | 项目入口、主线、排除项 |
| batch1 | 基础 | 实体卡片和开发资料索引 |
| batch2 | 需求变更 | 需求池、变更表、影响字段 |
| batch3 | 分支 | repo、分支、tag、确认、构建线索 |
| batch4 | 测试 | LIT、SIT、SQA、测试门禁、归档 |
| batch5 | 质量 | 市场问题、性能专题、版本、OTA |
| batch6 | 框架 | 项目生命周期框架 |
| batch7 | 实体图谱 | 角色、系统、产物、检查点 |
| batch8 | 后续方案 | 样例下钻和最终沉淀路线 |
| batch9 | 需求样例 | 2 到 3 条需求或变更链路 |
| batch10 | 分支样例 | 主干、IR、OTA、tag、version 文件 |
| batch11 | 质量样例 | 问题到修复、测试、OTA、复盘 |
| batch12 | 发布 OTA | 发布前、发布中、发布后闭环 |
| batch13 | 角色系统 | 主源、佐证源、职责边界 |
| batch14 | 端到端报告 | 项目级工作流报告 |
| batch15 | 通用模板 | 可复用模板和检查表 |

## 超时策略

默认使用小批次和有界超时。只有确认操作仍在推进且结果有价值时，才提高超时。

| 场景 | 初始超时 | 可提升到 | 停止条件 |
| --- | --- | --- | --- |
| 本地文件读取 | 120 秒 | 不提升 | 文件存在或不存在已确认 |
| 单个 Confluence 页面 | 120 秒 | 300 秒 | 正文或子页面已返回 |
| 小批量 Confluence | 300 秒 | 480 秒 | 关键页面基本读完 |
| Jira 单 Key | 60 秒 | 120 秒 | 状态、负责人、更新时间已返回 |
| Jira 小批量 Key | 180 秒 | 300 秒 | 5 个以内 Key 已返回 |
| 大 CSV 或图谱校验 | 120 秒 | 300 秒 | 结构和数量已验证 |
| 汇总写作 | 300 秒 | 600 秒 | 报告和表格已写入 |

## 并发策略

适合并发：

- 需求变更样例和分支版本样例。
- 质量问题样例和角色系统映射。
- 本地索引读取和校验命令。

不适合并发：

- 最终端到端报告。
- 通用模板创建。
- 编辑同一个文件。
- 依赖同一个下游样例的连续下钻。

## 停止条件

满足任一条件即可停止单批：

1. 已回答本批核心问题。
2. 已获得 2 条完整样例或 3 条半完整样例。
3. 继续探索需要大附件、构建、版本包下载或无边界扫描。
4. 当前资料只能证明字段存在，不能证明闭环，且缺口已经明确。
5. 已达到超时且没有出现高价值新增证据。

## 安全规则

- 除非用户明确要求，不执行 repo sync、编译、Jenkins 任务或 OTA 包下载。
- 不把凭据写入产物。
- 不把流程模板当成项目事实。
- 不把相邻产品线样例当成当前项目事实。
- 不把 Jira Closed 当成发布闭环。
- 不把 OTA 台账记录当成分支闭环。
