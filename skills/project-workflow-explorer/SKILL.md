# 项目工作流探索

## 概览

使用本技能时，把项目当作完整生命周期探索，而不是只看零散文档或 Jira 单据。优先以 Confluence 作为知识和事实主源，Jira 只作为状态和执行佐证，并明确标记每个结论是事实、推断还是待确认。

## 核心规则

- 先确认项目主线和排除项，再深入阅读资料。
- 优先使用 Confluence 目录图谱、页面树和页面正文。
- 使用 Jira 查看状态、负责人、更新时间、评论、Change、Review、Approval 和链接关系。
- 不把 Jira Closed 当成交付闭环。
- 不把 OTA 台账记录当成代码分支或版本包证据。
- 不把系统侧 CI 页面当成项目交付构建规则，除非项目证据明确确认。
- 每个批次都要控制范围和超时。
- 优先选择能贯穿多个阶段的样例，而不是无边界全量扫描。
- 最终报告必须保留证据边界。

## 资料源优先级

除非用户明确指定，否则按以下顺序取证：

1. Confluence 项目页面和目录图谱。
2. Confluence 流程、质量、版本和 OTA 页面。
3. Jira Issue、Change、Review、Approval 和 remote link。
4. SVN、PLM、TV-SLM、repo、version 文件、Jenkins、FTP 或 upload 路径、邮件证据。
5. 用户提供的业务背景。

## 工作流程

1. 确认项目主线。
   - 识别项目入口页、产品线、平台、芯片、机型或系列。
   - 列出纳入范围和排除方向。
   - 记录相关但次级的空间，例如 OS、部门、质量、测试空间。

2. 建立第一版图谱。
   - 先读目录或图谱摘要，再读页面正文。
   - 建立页面索引、实体索引和资料源边界。
   - 把正文为空的入口页视为子页面指针。

3. 按生命周期分批探索。
   - 范围和边界。
   - 项目基础资料和开发准备。
   - 需求和变更。
   - 分支、构建和开发协作。
   - LIT、SIT、SQA 和测试验证。
   - 质量问题、性能专题、版本管理和 OTA。
   - 角色和系统映射。

4. 用样例穿透。
   - 选择 2 到 3 条需求或变更样例。
   - 选择 1 条分支或发布样例。
   - 选择 2 到 3 条质量或 OTA 样例。
   - 每条样例都追踪上游输入、负责人、状态、实现、测试、发布和复盘。

5. 汇总沉淀。
   - 产出端到端项目工作流报告。
   - 产出阶段门禁和数据字段检查表。
   - 产出未闭合证据缺口和最小后续验证动作。
   - 在项目事实清楚后，再抽象可复用工作流方法。

## 输出模式

每个批次优先产出三类文件：

- `batchN-主题报告.md`
- `batchN-实体或样例表.csv`
- `batchN-缺口或风险清单.md`

每份报告都应包含：

- 范围和证据口径。
- 已读取页面或系统。
- 关键事实。
- 推断及推断理由。
- 证据缺口。
- 最小后续验证动作。

最终交付优先产出：

- 项目端到端工作流报告。
- 项目工作流检查点 CSV。
- 未闭合问题和后续验证清单。
- 可复用工作流模板和项目资料检查表。

## 校验规则

完成前必须检查：

- 每个关键结论都有来源。
- Jira 状态没有被当作测试、版本或发布闭环。
- OS、部门、流程等相关空间已标记为补充资料。
- 排除产品线没有混入主线。
- 线上访问操作使用了有界超时。
- 产出 CSV 时文件可解析。
