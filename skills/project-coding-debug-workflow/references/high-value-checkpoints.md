# 高价值检查点

## 1. 开发任务卡

处理开发或调试任务时，优先补齐以下字段：

| 字段 | 要求 |
| --- | --- |
| 任务来源 | Jira、DTV、CR、PLM、测试问题、市场问题或临时调试 |
| 项目范围 | 9655 内销主线或参考项目 |
| 机型版本 | 样机、软件版本、user 或 userdebug、构建时间 |
| 目标分支 | master、IR、OTA、新品鉴定或待确认 |
| MTK 对齐 | MTK tag、MTK 分支、`version.txt` |
| 现象证据 | 复现步骤、概率、日志、截图、视频、trace |
| 代码范围 | 仓库、模块、进程、包名、so、配置项 |
| 修改类型 | 临时验证、配置变更、代码修复、性能参数、MTK patch |
| 自测交接 | 用例、结果、未覆盖范围、风险、回归建议 |
| 闭环证据 | Review、commit、构建包、测试报告、发布观察、回灌 |

## 2. IR 和 OTA 合入检查

进入 IR 或 OTA 分支前，至少确认：

1. 目标分支名称。
2. 问题来源和问题号。
3. patch、diff、ko、配置或资源文件来源。
4. MTK tag 和 `version.txt`。
5. 影响机型和影响模块。
6. RD、PL、主设计、hisense 窗口、科室负责人邮件确认。
7. 构建产物、测试建议和回灌要求。

## 3. 调试取证检查

执行任何设备调试动作前，至少确认：

1. 样机和版本。
2. 是否允许写入。
3. 是否需要 root、userdebug、unlock、remount。
4. 修改是否可回滚。
5. 日志是否覆盖复现前、中、后。
6. 调试修改是否需要转成正式代码或配置修复。

## 4. 性能定位检查

性能问题先做分层，不直接上重工具：

1. 问题类型：CPU、内存、I/O、UI、播放、启动、网页、弱网。
2. 基础资源：`top`、`dumpsys meminfo`、`dumpsys gfxinfo` 等低侵入数据。
3. 进程和线程：pid、tid、线程名、时间窗口。
4. 深采工具：simpleperf、perfetto、atrace、ftrace。
5. 对比基线：优化前后、不同版本、不同配置或不同机型。

## 5. 代码问题检查

代码问题先判断阶段：

| 阶段 | 重点 |
| --- | --- |
| 编译期 | 构建文件、源文件是否参与编译、函数是否定义、vtable |
| 加载期 | 文件名、soname、NEEDED、运行路径、成组依赖 |
| 运行期 | core、tombstone、GDB、symbols、库路径 |
| 内存期 | malloc_debug、heap dump、symbols、前后对比 |

## 6. 测试交接检查

转测前至少提供：

1. 背景和任务来源。
2. 改动范围。
3. 版本和构建产物。
4. 自测环境、用例和结果。
5. 日志、截图、视频或 trace。
6. Review 和静态检查结论。
7. 测试建议、风险和未覆盖范围。
8. 已知问题和回滚方式。
