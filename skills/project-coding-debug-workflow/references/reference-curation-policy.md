# Reference 挑选规则

## 1. 总原则

`references/` 不是资料备份目录。只放能在后续任务中稳定提高判断质量、降低误判风险、减少重复探索的内容。

不把 batch17 到 batch22 的完整 SOP 全量复制进 skill。完整材料保留在工作目录，通过 `local-artifact-index.md` 指向。

## 2. 应该加入 reference 的内容

1. 项目特异边界。
   例如 9655 内销是主线、JuOS 是系统侧补充、商显和激光暂不关注。

2. 高风险误判规则。
   例如 Jira Closed 不是闭环、OTA 台账不能反推分支、JuOS CI 不能替代内销构建规则。

3. 高频任务卡模板。
   例如开发任务卡、自测交接、IR/OTA 合入确认、性能交接字段。

4. 专项 SOP 路由。
   例如设备、日志、性能、代码、构建分支五条线如何选择。

5. 项目事实检查点。
   例如主干分支、`version.txt`、MTK tag、0414 和 0513 分支关系待确认。

## 3. 不应该加入 reference 的内容

1. 普通命令说明。
   例如 `top`、`logcat`、`grep`、`adb push` 的基础用法，除非它们绑定了项目特定前置条件和风险。

2. 大段 Confluence 原文。
   尤其不能搬运包含账号、凭据、内部地址细节的内容。

3. 已经在 batch SOP 中完整保存的泛化流程。
   只在 reference 中保留入口和关键判断，不重复全文。

4. 一次性探索过程记录。
   搜索词、临时页面列表、已经被整理过的原始过程不放入 skill。

5. 未验证的推断。
   推断可以写入待确认清单，但不能写成工作规则。

## 4. 判断标准

一条内容只有满足以下至少两项，才适合进入 reference：

1. 后续任务很可能反复用到。
2. 一旦忘记会导致错误分支、错误构建、错误闭环或高风险设备动作。
3. 需要项目上下文才能正确理解。
4. 不能靠通用模型常识可靠推断。
5. 能帮助 Agent 少问问题、少重复探索。
