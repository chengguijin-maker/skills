# 日志体系参考

## 1. 使用边界

日志体系线用于 logcat、kernel log、DTV 日志、Audio、HDMI、DP、Dolby、HUI、pstore、bugreport、日志上报和错误日志分析。

日志不是越多越好，重点是覆盖复现前、中、后，并能和版本、机型、输入源、操作动作、时间点对齐。

## 2. 先确认的问题

1. 问题模块是什么：DTV、Audio、HDMI、DP、Dolby、HUI、系统、应用、性能。
2. 复现场景是什么：输入源、片源、网络、外设、操作路径、持续时间。
3. 日志采集窗口是什么：复现前、复现中、复现后。
4. 输出路径和空间是否足够。
5. 是否需要同步截图、视频、trace 或 bugreport。

## 3. 高价值日志证据

| 场景 | 关键证据 |
| --- | --- |
| 系统问题 | logcat、kernel、bugreport、pstore、时间点 |
| DTV 问题 | DTV 模块日志、输入源、信号、频道、复现步骤 |
| Audio 问题 | 片源、输出格式、外设、透传、功放、Audio log |
| HDMI 问题 | EDID、对比机、HDMIRX、xc、dmesg、串口日志 |
| DP 问题 | DP/HDMI 相关底层日志、寄存器或状态输出 |
| Dolby 问题 | Dolby 专项日志、片源、模式、输出链路 |
| UI 或性能 | logcat、gfxinfo、perfetto、atrace、视频 |
| 崩溃问题 | tombstone、core、logcat、符号和版本 |

## 4. 日志交接字段

| 字段 | 要求 |
| --- | --- |
| 版本 | 软件版本、构建时间、分支或包名 |
| 场景 | 输入源、操作步骤、片源、网络、外设 |
| 时间 | 问题发生时间点、采集开始和结束时间 |
| 日志类型 | logcat、kernel、DTV、Audio、HDMI、bugreport 等 |
| 附件 | 日志文件、截图、视频、trace、问题编号 |
| 结论 | 已证实、推断、待确认分开写 |

## 5. 不要误用

1. 不要只有异常截图，没有日志和时间点。
2. 不要把日志里出现的最后一个错误直接当根因。
3. 不要把其他平台日志开关直接当 9655 内销规则。
4. 不要在报告里保留账号、凭据或敏感原文。
