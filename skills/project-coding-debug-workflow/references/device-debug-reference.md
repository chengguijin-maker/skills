# 设备调试参考

## 1. 使用边界

设备调试线用于 adb、remount、串口、升级、替换文件、logcatd、bugreport、pstore 等任务。

执行前必须确认：

1. 样机、机型、软件版本、user 或 userdebug。
2. 是否允许写入设备。
3. 是否需要 root、unlock、disable-verity、remount。
4. 是否有回滚方式。
5. 当前动作是临时验证还是正式修复的一部分。

## 2. 关键判断

1. `remount`、overlayfs、push 文件、替换 so 只证明临时验证，不证明量产修复。
2. 替换系统文件前要确认目标分区、权限、SELinux、文件架构和原文件备份。
3. 串口、boot、factory、key、升级相关动作属于高风险设备状态变更，不能默认执行。
4. user 版本抓日志能力和 userdebug 不同，不能套用同一套命令。
5. 升级、擦分区、写 key、关闭校验等动作必须先有用户明确要求。

## 3. 交接字段

| 字段 | 要求 |
| --- | --- |
| 样机信息 | 机型、主板、版本、user 或 userdebug |
| 调试目的 | 为什么要执行该动作，预期验证什么 |
| 操作动作 | adb、串口、remount、push、升级等 |
| 前置条件 | root、unlock、网络、U 盘、串口、权限 |
| 输出证据 | 日志、截图、视频、命令输出、文件校验 |
| 风险 | 是否会影响样机状态、数据、key、分区 |
| 回滚 | 如何恢复原文件、属性、分区或版本 |

## 4. 不要放大的结论

1. 替换文件后现象消失，不等于正式代码已经修复。
2. remount 成功，不等于构建包包含修复。
3. 升级成功，不等于目标问题已回归通过。
4. 设备能复现，不等于已经定位到代码根因。
