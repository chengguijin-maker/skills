# 构建和分支参考

## 1. 使用边界

构建分支线用于目标分支确认、IR、OTA、version.txt、MTK tag、构建参数、构建产物、Jenkins 只读确认、升级验证交接和回灌判断。

默认不执行：

```text
repo sync
编译
Jenkins
下载版本包
设备升级
写入设备
```

## 2. 目标分支判断

先确认任务属于哪类：

| 分支类型 | 使用场景 |
| --- | --- |
| master | 主线开发和后续交付分支来源 |
| IR | 首单量产、新品鉴定、指定量产交付 |
| OTA | 线上修复、灰度、全量发布 |
| 新品鉴定 | 阶段验证和新品收敛 |
| JuOS | 系统侧补充，不替代 9655 内销主线 |

分支未确认前，不做代码修改、构建、合入、升级或测试交付。

## 3. 9655 已知检查点

主干：

```text
hisense_aosp_14_mt9655_master
```

关键文件：

```text
vendor/mediatek/tv/build/version/version.txt
```

仍需确认：

1. 0414 和 0513 OTA 分支关系。
2. 9655 内销独立 Jenkins 任务和产物路径。
3. IR 和 OTA 邮件确认模板和归档位置。
4. 合入后是否必须回灌 master 或当前 OTA 收敛分支。

## 4. IR 和 OTA 合入字段

至少记录：

| 字段 | 要求 |
| --- | --- |
| 目标分支 | master、IR、OTA 或新品鉴定 |
| 问题来源 | Jira、DTV、PLM、CR、市场或测试问题 |
| patch 内容 | commit、diff、ko、配置或资源文件 |
| MTK 对齐 | MTK tag、MTK 分支、version.txt |
| 影响范围 | 机型、模块、输入源、系统侧影响 |
| 确认人 | RD、PL、主设计、hisense 窗口、科室负责人 |
| 构建产物 | 任务、包名、时间、路径或构建记录 |
| 回灌要求 | master、OTA、IR 或后续分支是否同步 |

## 5. 构建交接字段

| 字段 | 要求 |
| --- | --- |
| 构建方式 | 本地全编、单编、Jenkins、每日构建、贴片 |
| 构建命令 | 命令、参数、job、log 文件 |
| 构建环境 | 服务器、Docker、内存、swap、路径 |
| 构建产物 | 包名、路径、时间、构建号 |
| 自测结果 | 样机、版本、用例、日志、视频 |
| 测试交接 | LIT、SIT、专项测试、风险和回归建议 |

## 6. 不要误用

1. 不要把 JuOS 构建命令写成 9655 内销主线规则。
2. 不要把 OTA 台账反推成代码分支或构建包。
3. 不要把 Jira Closed 写成构建、测试或发布闭环。
4. 不要把待实验单编命令写成稳定流程。
5. 不要把历史构建耗时写成固定承诺。
